## 0. 一句话形态

**pr-agent 收缩成一个「开发链执行器 + 判据工具面」**：
输入 repo + 需求，输出到 PR 为止；卡片、对话、入口、最终合入决策**全部归 Hermes**。

### 1.1 保留的 6 步链（原 8 步）

```
checkout → coding → test → review → commit → push-open-pr
```

| # | 步 | 谁在做事 | 相对现状的改动 |
|---|---|---|---|
| 1 | `checkout` | 程序（git） | 原样 |
| 2 | `coding` | Claude Code CLI | 换 SDK（去掉 `@mastra/claude`） |

### 1.3 判据归属（本次最重要的一组决策）

**程序只产出事实，不做决策。**

| 原程序判据 | 位置 | 处置 |
|---|---|---|
| `testsPassed`（用 exit code 判通过与否） | `:806-807` | ⬇️ **降级为事实**：仍记录 exit code / 命令 / 耗时，但**不再合成布尔结论** |
| `agentModifiedTests` 的**阻断** | `:853-863` | ❌ 去掉阻断；检测结果**作为事实上报**（"agent 改了这些测试文件"仍然是有价值的信息） |
| `passed` 程序合成 | `:892` | ❌ 去掉 → `passed = llm.requirementMet` |

**阻断策略（保留一处、去掉一处）**：

| 位置 | 现状 | 变更后 |
|---|---|---|
| test 判 `requirementMet=false` | `:951` `if (!passed) {` | ✅ **保留阻断**（判据来源变为纯 LLM） |
| review 判 `request-changes` | `:1010` `if (reviewResult.decision === 'request-changes') {` | ❌ **不再阻断** → 结论随链上报，由 Hermes 兜底决定 |

**理由**（用户决策）：test 判负意味着"需求根本没实现"，继续跑只会白烧资源；
review 判负是"实现得不够好"，有价值的是**意见本身**，阻断反而让 Hermes 看不到完整信息。

⚠️ **这是一次有意识的降级，只记不辩**：去掉 `agentModifiedTests` 的阻断后，
**「agent 自己把既有断言改松、然后自证通过」这类失败不再被程序拦住**。
- 原设计意图（`dev-workflow.ts:842-851`）：测试是**需求的可执行规格**，agent 改它等于改考卷；
  这与"测试红了"是两种不同的失败 —— 前者是**判据被动过**，后者是**产物不合格**。
- **可推翻条件**：当需要「这条结论**是谁**得出的、**可信度**多少」而不只是**结果**时，"交给 LLM 评审"就不够了。

## 3. 编排壳

**薄接口包住，内部先留 Mastra**：

```ts
export async function runDevWorkflow(input: DevInput): Promise<DevRunResult>
```

**为什么是"包住"而不是"立刻重写"**：
- 7 个 verify 脚本当前调 `mastra.getWorkflow('dev-workflow')` + `createRun()` + `start()`
  → 改为调这个接口后，**以后换实现只动一个文件**
- 一次只改一个变量：本轮改的是「运行位置 + 范围」，架构形态留到有实测证据再动

**卡点 1（状态载体）已消失**：
dev run 到 PR 就**完结**，没有「挂起等人工」→ **不需要 suspend/resume** → 不需要持久化快照。
`mastra/index.ts:31-41` 的注释自证 storage 的**唯一用途**就是跨进程 resume。

**替代需求**：`runId → (repo, branch, prNumber)` 的持久映射
→ 用现有 `log-store`（纯 fs）或 `state-db` 加一张表即可，**无需自建快照层**。

## 4. LLM 抽象

**有对象，且落点明确。** pr-agent 有 2 类 LLM 消费方：

| 消费方 | 形态 | 位置 | 抽象落点 |
|---|---|---|---|
| `runGate` × 3 | **HTTP** | `:867` test / `:990` review / `:1043` commit | `providers.ts` |
| `coding` | **Claude Code CLI**（非 HTTP） | `coding-agent.ts` | 独立适配层 |

**现状与要改的**：

```ts
// providers.ts:50
export type LlmProtocol = 'openai-compatible';   // ← 只有这一个值

// providers.ts:45-46 注释：会「拒绝非 openai-compatible 的 provider 并给出明确指引」
```

且 `toMastraModelConfig`（`:238-245`）只产出 `OpenAICompatibleConfig`。

**要做的**：把 `LlmProtocol` 扩为 `'openai-compatible' | 'anthropic-messages'`，
并让模型配置的产出按协议分支。**claude 优先，OpenAI 格式预留。**

📌 **用户原话**：「不同的 LLM 需要提前抽象一下，暂时可以先只支持 claude，后续可能切换成 OpenAI 的格式」
——「格式」一词只对 HTTP 成立（`/v1/messages` vs `/chat/completions`），与 CLI 无关。
