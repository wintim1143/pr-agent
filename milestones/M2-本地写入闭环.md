## 0. 角色与责任 🟦

| 角色 | 是谁 | 在本里程碑做什么 / 何时介入 |
|---|---|---|
| 触发方 | **开发者手动触发**（脚本 / curl） | M2 不接 IM 入口：`dev-workflow` 的入参是 issue 形状对象，由验证脚本构造后 `createRun().start()`。飞书 inbound 属 M5，本里程碑不依赖 |
| 审批方 | **运行时无闸门** | M2 的 commit 直接落在本地 feature 分支，不 suspend。人工闸门在 M3 的 merge 步才引入 |
| 验收方 | **用户（人工）** | 用户规则：AC 全绿 + 人工验收通过，才算完成。验收动作 = 跑 `scripts/verify-local-write.js` + 亲自 `git log` 检查沙箱仓库 |
| 卡 Owner | 当前开发会话 | 推进并更新本卡 |

> ⚠️ **运行时无闸门 ≠ 无需人工把关**。M2 的把关在**里程碑层**（跑完人来看结果），不在**编排层**（不 suspend）。这是因为 M2 对远端零影响，放行的代价可控；M3 一旦要 push/merge，闸门必须回到编排层。

## 1. 目标（一句话）🟦

**给定一条 issue 形状的入参，dev-workflow 在隔离的沙箱仓库里真建 feature 分支 → 真起编码 agent 改文件 → 过三个质量闸门 → 真 commit 落本地分支；全程 `main` 不动、远端不动、围栏红线拦得住。**

## 3. 范围 / 明确不做 🟦

**做**

- 目标仓库可配置（`CODING_REPO_ROOT` 指向隔离沙箱），checkout/coding/commit 落在同一仓库
- `checkout` 真建分支 `feat/<issueNumber>-<slug>`
- `coding` 真起 Claude Code CLI 改文件（`git diff` 可见）
- `test` / `review` / `commit` 三闸门跑通，输出能被 zod 结构化解析（**仍是 LLM 自评**）
- `commit` 真落盘到本地 feature 分支
- **红线实证**：受保护路径、危险命令、越界写入三类拦截真拦得住
- 端到端验证脚本 + AC 矩阵 + flow 图

**明确不做**（留给后续里程碑）

- **不 push、不开 PR**（M3）；**不 merge**（M3，且是人工闸门）
- **不真跑 `npm test` / 真喂 `git diff` 给 review / commitlint 真校验**（M4）——M2 三闸门仍是 LLM 自评，只要求输出结构化
- **不接飞书 inbound、不做按钮回调**（M5）
- 不做多仓库、不做 GitHub App 鉴权、不做幂等防重复（M5）
- 不做 run 追踪 / 成本回写 / 失败重试告警（M6）

## 6. 用到的 Mastra 模块 🟨

| Mastra 模块 | 导入路径 | 职责 | 为什么用它，而不是裸写 |
|---|---|---|---|
| `Workflow` / `createStep` | `@mastra/core/workflows` | 强制步骤顺序，保证「没编码就没测试、没审核就没 commit」 | 顺序即闸门。裸写脚本可以随意跳过，`Workflow` 的 `.then()` 链让跳过变成显式改造 |
| `ClaudeSDKAgent` | `@mastra/claude` | 编码执行体，真读写文件 | 复用 Claude Code CLI 原生工具链（Read/Edit/Write/Bash/Glob/Grep）。自造 `createTool` 要重实现一整套 + 错误恢复，每个边界都是漏洞点 |
| PreToolUse hook | `@anthropic-ai/claude-agent-sdk` | 唯一可靠拦截点 | `bypassPermissions` 下 `canUseTool` 回调**根本不会被调用**（SDK 源码明确）。只有 hook 能拦住每一次调用 |
| `agent.generate` + `structuredOutput` | `@mastra/core` | 三闸门输出结构化，供条件边判定 | 避免解析字符串。M4 换真判据时，字段名不用动 |

**选型备注**：评估过「Mastra 原生 agent + 自造工具链」（可绕开 CLI 依赖与 `reg.exe`），因工具链与错误恢复成本过高放弃，理由同上表第 2 行。

## 10. 异常与兜底 🟨

> 判定条件必须可执行（返回码 / 超时秒数 / 配置缺失），不许写「可能出问题就兜底」。

| 已知异常 | 判定条件（可执行） | 降级行为 | 是否阻断 AC |
|---|---|---|---|
| 编码后端凭据缺失 | `missingCodingCredentials()` 返回 `true` | coding 步返回 `(SKIPPED_NO_CREDENTIALS: 编码未执行)` 并 `console.error` | **是**（AC-2/3） |
| 编码 agent 执行抛错 | `agent.generate()` reject | 返回 `(ERROR: <msg>)` 并 `console.error` | **是**（AC-2/3） |
| **CLI 子进程挂起** | `generate()` 超过 N 秒未返回（当前**无超时守卫**） | 无 → 整条 workflow 冻住 | **是**（全部）。**M2 待补**：加 `CODING_TIMEOUT_MS` 守卫 |
| `CODING_REPO_ROOT` 非法 | 目录不存在 / 缺 `.git` | `getRepoRoot()` 显式抛错 | **是**（全部） |
| checkout 建分支失败 | `githubCheckout()` reject | **当前 catch 后返回占位分支名 `feat/<n>-dev` 并仅 warn** | ⚠️ **隐患**：AC-1 会误判通过。M2 待改：失败应显式暴露并阻断 |
| commit 无改动可提 | `gitCommit()` 返回 `committed:false, error:'nothing-to-commit'` | 仅 warn，流程继续 | **是**（AC-8） |
| 闸门结构化解析失败 | `structuredOutput` 的 `errorStrategy:'strict'` 抛错 | workflow 失败 | **是**（AC-7） |
| 沙箱仓库工作区不干净 | 运行前 `git status --short` 非空 | 无 → 无关改动可能被 `git add -A` 卷进 commit | **是**（AC-8）。M2 待加：运行前前置检查 |
| 沙箱被污染需重来 | 人工判断 | `cd D:\code\pr-agent-sandbox && git checkout main && git reset --hard <初始sha> && git branch -D feat/*` | — |

> **三条「M2 待补/待改」是本卡从设计期就暴露的缺口**，不是事后发现：coding 步无超时守卫、checkout 失败静默降级、缺运行前洁净检查。它们的共同点是**失败不显式**，会让人看到「全绿」的假象——M1 的 LLM 降级就是这么踩的。
