## 为什么重排：从「纵向切层」改成「横向切片」

旧的 S0–S6 是按**技术层**纵向切的（S2 编码、S3 闸门、S4 端到端、S5 飞书……），
问题是**只有走到 S4 才能第一次看到完整链路跑起来**，前几步都是看不见的地基。

新的划分原则：**每个里程碑都是一条端到端可演示的切片**，功能从薄到厚，每一步都有可见产出。

| | 旧（S0–S6，纵向切层） | 新（M1–M6，横向切片） |
|---|---|---|
| 组织方式 | 先做地基，最后才串联 | 先跑一条最细的线，再逐段加粗 |
| 首次可见效果 | S4（第 4 步） | **M1（第 1 步）** |
| 风险暴露 | 晚期集中爆发 | 每个里程碑暴露一批 |
| 对目标仓库的写入 | S2 就要写 | **M1、M2 完全不写远端** |

## 里程碑间解锁关系

每个里程碑都是「薄切片」，但切片之间不是孤立的——前一个跑通后沉淀的可复用基建，直接变成后一个的起跑线。下表把这条递进链显式写出来（M2–M6 卡未建，解锁关系先按路线图标预期；建卡后在各自 §解锁与复用 回填实际复用）。

| 里程碑 | 沉淀的可复用基建 | 解锁的下一里程碑能力 |
|---|---|---|
| **M1 只读洞察** | `githubIntegration` / `feishuIntegration`（继承 `Integration` 基类）、`insight-workflow` 四步编排骨架（collect→summarize→notify→confirm + `suspend/resume`）、LibSQLStore 跨请求恢复 | **M2**：复用同一 GitHub client 扩展出写分支 / commit；复用 workflow 骨架，把 step2 换编码 agent、step4 换「开 PR 确认」 |
| **M2 本地写入** | 编码 agent 真改文件 + 真 commit 的端到端（本地）、guard 权限围栏在写场景的验证 | **M3**：在 M2 基础上加 push + 开 PR + squash merge |
| **M3 完整 PR** | push + 开 PR + merge 全链路；**D4 目标仓库选型在此落定** | **M4**：在真实 PR 上挂真质量闸门 |
| **M4 真闸门** | `npm test` 真跑 / `git diff` 真喂 review / commitlint 真校验（替换 LLM 自评） | **M5**：把闸门扩展到多仓库 + GitHub App 鉴权 |
| **M5 多仓库** | RepoTarget 多仓库、GitHub App 鉴权、幂等防重触发 | **M6**：在稳定的多仓库上做可观测与成本 |
| **M6 可观测** | run 追踪、成本回写、失败重试与告警 | （终点） |

## 全局原则

1. **每个里程碑必须有一条可演示的链路**，不接受「只加地基、看不到效果」。
2. **不写远端仓库的先做**。M1/M2 全部只读或只写本地分支，避免污染历史、也绕开了 D4（目标仓库选型）这个未决项。
3. **能用 Mastra 官方抽象就不裸写**。同样一个功能，优先落到 Mastra 的模块上（Integration / Tool / Workflow / Storage / Agent），
   而不是自己 new 一个 fetch 封装——这样踩过的坑和学到的东西是可迁移的。
4. **每张卡按 🟦定义期 / 🟨实施期 分层填写**（模板第 1–4 节定义期必填，第 5–10 节实施期渐进补全）。源码级证据（行号 / 实测命令 / 接口路径）只进「实施日志·已核实事实」，不进正文。
5. **完成后立刻归档**：改了什么、重点模块、踩坑，写进实施日志，不等到里程碑收尾。
6. **每个里程碑配一张数据流向图（流程图 / 时序图）**，展示「触发 → 编排 → 集成 → 外部系统」及 suspend/resume 断点。推荐用 Mermaid 写在独立文件 `M<n>-<名称>-flow.md`，卡片只放链接。
7. **记录不强制单文件**：里程碑卡可只做索引，链路图 / 流程图 / 实施日志 / 复盘等拆到同目录的独立文件（或子目录），便于单篇查看与演进。

## 目录约定

```
milestones/
├── README.md                          ← 本文件：总路线图
├── _template-里程碑卡.md                ← 新里程碑照此模板建（🟦/🟨 分层）
├── M1-只读洞察闭环.md                   ← 当前里程碑卡（索引 + 十节文本）
├── M1-只读洞察闭环-flow.md              ← M1 数据流向图（Mermaid 流程图/时序图）
└── M2-<名称>.md / M2-<名称>-flow.md     ← 后续按 M2/M3... 递增，章图可拆独立文件
```

单个里程碑卡统一包含十节（🟦=定义期必填，🟨=实施期渐进补全）：

1. 🟦 目标（一句话）
2. 🟦 为什么现在做（排序理由）
3. 🟦 范围 / 明确不做
4. 🟦 端到端演示效果
5. 🟨 链路图
6. 🟨 用到的 Mastra 模块（重点）
7. 🟨 任务分解（每个任务带验收）
8. 🟨 验收清单（AC）
9. 🟨 解锁与复用
10. 🟨 实施日志（**持续追加**）

> 数据流向图为必配项，但**不占这十节编号**——它独立成文件 `M<n>-<名称>-flow.md`，卡片 §5 只放链接。如需把链路图 / 实施日志也拆出去，同样独立成文件、卡片留索引即可。
